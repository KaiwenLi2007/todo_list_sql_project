--- PHASE 1: Database & schema ---

PROMPT (paraphrased):
  Initialize Database: Connect to a SQLite file named course_manager.db.
  Define Schema: Create a table tasks with: id (PK, auto-increment Integer),
  course_name (Text, required), deadline (Text/ISO8601 YYYY-MM-DD), est_hours
  (Float), urgency_score (Text, generated by system logic).

OUTCOME:
  - init_db.py: get_connection(), init_db(), CREATE TABLE tasks. DB path
    course_manager.db in project root. Schema created and verified with sqlite3.


--- PHASE 2: CRUD & main loop ---

PROMPT (paraphrased):
  Operational Commands (CRUD):
  - CREATE: Prompt for course_name, deadline, est_hours; run Urgency Engine;
    INSERT; notify success and urgency level.
  - READ: Option A sort by deadline ASC, Option B sort by urgency_score ASC;
    display formatted table.
  - UPDATE: Show tasks, ask id and new_est_hours; re-run Urgency Engine;
    UPDATE tasks SET est_hours = ?, urgency_score = ? WHERE id = ?.
  - DELETE: Ask id; DELETE WHERE id = ?; verify and confirm.
  Main loop: START → INIT Database → WHILE user_choice != "Exit": display
  menu 1–5, call corresponding command.

OUTCOME:
  - urgency_engine.py: compute_urgency(deadline, est_hours) with buffer logic
    (Buffer = Available_Hours - est_hours; <24h → 1-HIGH, <72h → 2-MEDIUM,
    else 3-LOW). Deadline as end-of-day.
  - main.py: cmd_create(), cmd_read(sort_by_date), cmd_update(), cmd_delete();
    main() with init_db() and menu 1–5 (Add, View by Date/Urgency, Update,
    Delete, Exit). Plain table formatting.


--- PHASE 3: Urgency engine (exact formula) ---

PROMPT (paraphrased):
  The Core Logic (Urgency Engine): Capture current_datetime and deadline_datetime.
  Available_Hours = (Deadline - Current_Time). Buffer = Available_Hours - est_hours.
  IF Buffer < 24h → "1-HIGH". ELSE IF Buffer < 72h → "2-MEDIUM". ELSE → "3-LOW".

OUTCOME:
  - urgency_engine.py rewritten to use end-of-day for deadline, total_seconds()/3600
    for available_hours, buffer_hours = available_hours - est_hours; thresholds
    24 and 72. main.py READ sort by urgency uses ORDER BY urgency_score ASC.

--- PHASE 8: Sorting and date parsing ---

PROMPT (paraphrased):
  Make the sorting feature better. The date should be able to identify the date
  both in the format of March, Mar, 03, 3 and sort them accordingly. Make a fancy
  looking user interface. Use HTML/CSS if needed.

OUTCOME:
  - date_parser.py: normalize_date() tries many formats (YYYY-MM-DD, March 15,
    Mar 15, 03/15, 3, etc.), returns YYYY-MM-DD. Handles month-only and numeric
    day/month.
  - app.py: POST create normalizes deadline with normalize_date; 400 if invalid.
    GET list: sort=deadline_asc | deadline_desc | urgency; date sort uses
    normalized date.
  - index.html: sort pills (Date ↑, Date ↓, Urgency); deadline input hint;
    formatDate() shows "Mar 15, 2025"; fancier layout and styles.

--- PHASE 12: 3-day + 6h = urgent; display HIGH; current data ---

PROMPT (paraphrased):

OUTCOME:

  - Current DB data reported: e.g. id 7 (15113, March 17, 20h), id 9 (15122,
    Mar 20, 10h), id 10 (15150, Mar 30, 50h); deadlines stored as "March 17" etc.
    explained why everything showed MEDIUM (non-YYYY-MM-DD previously not parsed).
